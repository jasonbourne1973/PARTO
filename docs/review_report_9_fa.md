## ۲. جزئیات اصلاحات

### ۲-۱. «except بی‌صدا» صفر شد (۳۷ → ۰)

در دور هشتم شمارش کردیم که ۳۷ نقطه فقط `pass` می‌کردند: نه لاگی، نه توضیحی.
این‌ها دو دستهٔ کاملاً متفاوت بودند و هرکدام درمان خودش را داشت:

**الف) تحلیل‌های محتملِ خطا (fallback):**

```python
try:
    month = int(date_str.split('/')[1])
    return f"{month_names[month-1]} {date_str[:4]}"
except Exception:          # ← دامنهٔ بی‌جهت پهن
    pass
```

اینجا fallback درست است، ولی `except Exception` خطاهای برنامه‌نویسی را هم
می‌بلعد. اصلاح:

```python
except (ValueError, IndexError, TypeError, AttributeError):
    # تاریخ ناقص یا نامعتبر: همان رشته برگردانده می‌شود تا بقیهٔ
    # تحلیل سالم بماند (این مسیر «خطا» نیست، fallback است).
    pass
```

**ب) عملیات جانبی (فایل، Audit، checkpoint):**

```python
except OSError as e:
    logger.debug(f"فایل پشتیبان حذف نشد ({record.file_path}): {e}")
```

**ج) مسیرهای اضطراری (rollback ناموفق، کنسول بسته):** با کامنت توضیحی و
`# noqa: S110` مستند شدند تا در بازرسی بعدی «مشکوک» شمرده نشوند.

سنجهٔ پذیرش در `verify_fixes9.py`: هیچ `except` که بدنه‌اش فقط `pass` باشد و
نه لاگ داشته باشد و نه کامنت بالای آن، باقی نمانده باشد → الان صفر است.

### ۲-۲. لایهٔ داده: استثنای عام → استثنای مشخص (۸۲ مورد)

```python
# پیش از اصلاح
except Exception as e:
    logger.error(f"خطا در دریافت مشاهدات کلاس: {e}")
    return []

# پس از اصلاح
except (sqlite3.Error, OSError, KeyError, IndexError,
        TypeError, ValueError, AttributeError) as e:
    logger.error(f"خطا در دریافت مشاهدات کلاس: {e}")
    return []
```

خطاهای برنامه‌نویسی (`NameError`، `ImportError`، `MemoryError`، …) دیگر
به لیست خالی و پیام «خطا در دریافت…» تبدیل نمی‌شوند و در تست‌ها می‌شکنند —
یعنی باگ‌ها سریع‌تر دیده می‌شوند.

**نکتهٔ مهم دربارهٔ سرویس‌ها:** در `services/` عمداً این کار انجام نشد.
متدهای سرویس «مرز تبدیل خطا» هستند:

```python
except Exception as e:                     # noqa: BLE001 - مرز سرویس
    self.db.discard_pending_writes()
    raise ServiceError(f"ذخیرهٔ پیشنهاد شکست خورد: {e}") from e
```

هدف این است که هر شکستی به پیام فارسی گویا برای کاربر تبدیل شود. همین
سیاست در `views/` هم حاکم است (مرز UI: برنامه هرگز نباید کرش کند).
به‌همین‌دلیل ۴۵۵ مورد `BLE001` باقی‌مانده **بدهی نیست، سیاست است** و در
`ruff.toml` و این گزارش مستند شده است.

### ۲-۴. Migration نسخهٔ ۹ — یکدست‌سازی دادهٔ موجود

دور هشتم مسیرهای *نوشتن* را یکدست کرد، ولی دیتابیس‌های موجود ردیف‌های قدیمی
با قالب مخلوط دارند. چون SQLite مقایسه را رشته‌ای انجام می‌دهد، این مخلوط
باعث می‌شد بازه‌های تاریخی بعضی ردیف‌ها را از قلم بیندازند:

```
'1405-6-6'       →  '1405/06/06'   ✅
'۱۴۰۵/۰۶/۰۶'      →  '1405/06/06'   ✅
'بوق' / NULL      →  دست‌نخورده       (فقط شمارش می‌شود)
```

- ۲۰ ستون تاریخ‌دار پیمایش می‌شود (`observations.observation_date`،
  `interventions.date`، `followups.date`، `students.birth_date`، …).
- فقط مقدارهایی بازنویسی می‌شوند که «تاریخ شمسی معتبر» تشخیص داده شوند
  (بازهٔ سال ۱۳۰۰–۱۵۰۰) تا متن آزاد یا تاریخ میلادی خراب نشود.
- idempotent است و در تست، مسیر واقعی ارتقاء `۸ → ۹` هم بررسی می‌شود.
