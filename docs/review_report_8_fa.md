## ۲. جزئیات اصلاحات

### ۲-۱. سیاست زمانی واحد (UTC)

**مسئله:** بخشی از کد با `datetime.now()` (زمان محلی، بدون ناحیهٔ زمانی)
مهر زمانی می‌ساخت و بخشی با `CURRENT_TIMESTAMP` (UTC). نتیجه: در یک ستون
واحد دو فرمت با هم قاطی می‌شد:

```
'2026-09-19T14:32:10.123456'      ← پایتون، محلی، جداکنندهٔ T
'2026-09-19 10:02:10'             ← SQLite، UTC، جداکنندهٔ فاصله
```

چون مقایسهٔ SQLite رشته‌ای است و کد نویسهٔ `T` بزرگ‌تر از فاصله است،
مقایسه‌ها به‌طور خاموش غلط می‌شد. یک نمونهٔ واقعی: `NotificationDAL.delete_old`
اعلان‌های تازه (چند دقیقه پیش) را در بازهٔ «قدیمی‌تر از ۳۰ روز» می‌دید.

**اصلاح:** فایل تازهٔ `utils/time_utils.py` به‌عنوان تنها منبع زمان پروژه:

```python
utc_now()          # datetime آگاه از منطقهٔ زمانی (UTC)
utc_now_iso()      # '2026-09-19T13:50:37.679423+00:00'
utc_now_sql()      # '2026-09-19 13:50:37'  ← سازگار با CURRENT_TIMESTAMP
utc_shift_iso(days=-7)      # برش زمانی به فرمت ISO
utc_shift_sql(days=-7)      # برش زمانی به فرمت SQLite
parse_timestamp(value)      # تحمل ISO، فاصله‌دار و محلی
age_days(value) / is_older_than(value, days=…)
```

۴۲ فایل (۱۲۶ نقطهٔ فراخوانی) به این توابع مهاجرت کردند. سه مورد باقی‌مانده
که در اسکن دوباره پیدا شد — متدهای زمانی مدل‌ها (`mark_as_read`،
`implement`، `complete`، `achieve`) و تاریخ‌های نام فایل خروجی — هم یکدست شدند.

### ۲-۲. اعتبارسنجی و یکدست‌سازی تاریخ شمسی

**مسئله:** سرویس‌ها فقط «شکل» تاریخ را می‌سنجیدند، نه اعتبار تقویمی:

```python
PersianDate.is_valid_persian_date('1405/13/45')   # True  ← ماه ۱۳ و روز ۴۵!
```

و در نقطهٔ مقابل، بعضی سرویس‌ها ورودی خط‌تیره‌دار (`1405-6-6`) را که از
فایل اکسل می‌آید رد می‌کردند.

**اصلاح:** کمک‌تابع مشترک `BaseService.check_date()` با قاعدهٔ سه‌مرحله‌ای:

```
«1405-6-6»    → نرمال‌سازی → «1405/06/06» → تأیید در تقویم → ✅
«1405/13/45»  → نرمال‌سازی → همان       → رد در تقویم    → ❌ با پیام گویا
''            → در فیلد اجباری ❌ / در فیلد اختیاری None
```

این تابع در ۶ سرویس به‌کار رفت: `student`، `counseling`، `observation`،
`intervention`، `followup`، `extracurricular`، `goal`. همچنین
`StudentService` مقاوم شد:

```python
StudentService._validate(...).father_name.strip()   # قبلاً: AttributeError روی None
```

و پنجرهٔ سال تولد به‌جای عدد ثابت، پویا شد: از ۱۳۷۵ تا سال جاری (با
fallback ۱۴۱۰ اگر تبدیل تقویم در دسترس نباشد).

### ۲-۳. ایندکس‌گذاری کلیدهای خارجی — Migration نسخهٔ ۸

**مسئله:** مقایسهٔ همهٔ ستون‌های `FOREIGN KEY` با ایندکس‌های موجود نشان داد
۳۳ ستون هیچ ایندکسی ندارند (مثلاً `observations.competency_id`،
`followups.intervention_id`، `screenings.student_profile_id`). SQLite برای
هر JOIN مجبور به پیمایش کل جدول بود.

**اصلاح:** `database/migrations/migration_v8.py` با ۴۳ ایندکس:

```python
("idx_observations_competency_id", "observations", "competency_id"),
("idx_followups_intervention_id", "followups", "intervention_id"),
("idx_audit_logs_entity", "audit_logs", "entity_type", "entity_id"),
...  # ۴۶ ورودی، بعضی چندستونی
```

- همه با `CREATE INDEX IF NOT EXISTS` ⇒ **idempotent**؛ در فهرست
  `_IDEMPOTENT_MIGRATIONS` ثبت شد تا روی دیتابیس‌های قدیمی هم اجرا شود.
- `DB_VERSION` از ۷ به ۸ رفت.
- نتیجه روی دیتابیس تازه: **۰ ستون کلید خارجی بدون ایندکس** (پیش از اصلاح: ۳۳).

### ۲-۵. از `print` به Logger

۱۴۳ `print` در لایهٔ داده، سرویس‌ها، ابزارها و صفحه‌های UI به Logger
منتقل شدند. نمونهٔ خطای بی‌صدا:

```python
except Exception as e:
    print(f"خطا در دریافت آمار مشاهدات کلاس: {e}")   # ← در GUI هیچ‌جا دیده نمی‌شود
    return {}
```

در برنامهٔ دسکتاپ (بدون کنسول) این پیام‌ها به هیچ‌جا نمی‌رفتند و کاربر فقط
«گزارش خالی» می‌دید. حالا:

```python
except Exception as e:
    logger.error(f"خطا در دریافت آمار مشاهدات کلاس: {e}")
    return {}
```

`print` های عمدیِ خط فرمان (`main.py`، migration ها، وضعیت راه‌اندازی
دیتابیس) دست‌نخورده ماندند، چون برای کاربر کنسول نوشته شده‌اند.

### ۲-۶. یک باگ که خودِ پاک‌سازی پیدا کرد

اجرای خودکار `ruff --fix` روی `config/settings.py` بلوک «بازصدور»
(Re-export) را حذف کرد:

```python
from config.constants import GRADES, STAFF_ROLES, ...   # ← «import بی‌استفاده» از دید ruff
```

ولی ۲۰+ ماژول از همین مسیر import می‌کنند (`from config.settings import GRADES`)
و سه فایل (`main_window`، `student_form`، `students_page`) بلافاصله شکستند.
اصلاح: بلوک با شکل صریح `X as X` بازگردانده شد (استاندارد PEP 484 برای
بازصدور عمدی) به‌همراه توضیح در فایل. همین کار برای `models/__init__.py`
و star-import آن انجام شد.
